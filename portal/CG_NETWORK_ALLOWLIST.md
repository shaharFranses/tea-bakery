## tea-bakery starter: outbound references and non-portal calls
- **The only runtime outbound reference is the CG SDK script**: `html/head_include.html:9`, baked into `build/web-debug/index.html:90` and `build/web-release/index.html:90`, and loaded conditionally (#5). Everything else in index.html is relative (same origin).
- **No non-portal network calls found:** no Google Fonts or other font CDN (fonts ship in the .pck), no Google Analytics / gtag / GTM, no Sentry, no `HTTPRequest` / `HTTPClient` / `WebSocketPeer` nodes or calls in any `.gd`, `.tscn` or `.tres`, no `OS.shell_open`, and no `fetch` or `sendBeacon` in our own JS glue. `JavaScriptBridge.eval` is used only for local page state: the PKD_CG / PKD_AUDIO / PKD_VIEW glue, `devicePixelRatio`, `matchMedia`, `location.search`, `performance.mark`. The `Analytics` sink is specified as no-op (`spec/SPEC.md:343`); not re-verified in code here.
- Engine capability present but unused: the stock template's index.js contains Godot's `GodotFetch` (HTTPRequest backend) and `GodotWebSocket`. They're inert unless game code uses them. The slim template disables `module_websocket_enabled` (`engine/pkd_slim_2d.py:49`).
- The pipeline starter's `qa/live_check.py` (`/workspace/pipeline-ops/starter/qa/live_check.py:90`, not yet in this repo) fetches `index.pck` from Pages over urllib. That's QA tooling outside the browser, so it isn't part of the run.

## How QA should apply it
1. **Scope the capture to the game frame.** Record CDP `Network.*` for the game's own target (top-level page in local/Pages runs; on CG the `*.game-files.crazygames.com` iframe target plus its workers). Don't judge the CrazyGames portal page: it has its own analytics and ads, which aren't ours.
2. **Allow:** #1–#3 (and #4 once confirmed) for game files; #5 when the glue is in portal mode; #6 only in a live `crazygames` env. **Fail on any other host.** Anything from #10–#12, or any font, analytics or tracking host, is a FAIL unless a written exception exists.
3. **Ads hosts (#7, #8) are expected only when ads are on** (Full Launch, `crazygames` env). In Basic, local or Pages runs, any hit on them is a FAIL. Even in Full, #8 hosts inside the game frame are expected only via #7's script; video ads belong to `games.crazygames.com`.
4. **Run matrix:**
   - (a) Local release, no flag. Expected: **only #1**, 0 `sendBeacon`. This is the run TT-AC-53 can fully pass today.
   - (b) Local release with `?cgsdk=1` (SDK local mode). Expected: #1 + `sdk.crazygames.com` only. No cza, no ads hosts. (The SDK shows ad overlays locally and makes no network ad calls.)
   - (c) CG Preview tool. Expected: #3/#4 + #5, **no #6** (`isQaTool`). Needs Shahar's logged-in upload.
   - (d) Live CG after Basic launch. Expected: #3 + #5 + **#6**, possibly #7/#8 in Full.
5. **⚠️ Fix the AC wording before a CG run.** TT-AC-53 says "0 `sendBeacon` calls". On live CG the **SDK itself** beacons to `cza.crazygames.com/event` (#6), and our `data.setItem`/`getItem` calls trigger it. Suggested text: "0 `sendBeacon`/`fetch` from game code; any `sendBeacon` must target `cza.crazygames.com` and originate from `crazygames-sdk-v3.js`." Runs (a) to (c) are unaffected.
6. Re-pull `crazygames-sdk-v3.js` before each QA run, diff its hostname set against this table, and update the table if a new host appears.
